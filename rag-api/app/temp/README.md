1. В данном варианте присутствует множество минусов таких как:

| Запрос пользователя | Проблема текущей реализации |
| --- | --- |
| Опиши акт 87 | Определяется документ №87 |
| Сравни акты 56 и 87 | Нет полноценного механизма выбора двух документов |
| Какие документы связаны с актом 87? | Поиск ограничивается актом №87, хотя нужны другие документы |
| Какие работы выполнены в прошлом месяце? | Поиск не понимает временные и предметные ограничения |
| Найди расхождения между договорами и актами | Нет механизма анализа связей между документами |
| Что означает слово «акт» в законодательстве? | При наличии документа в контексте может ошибочно запускаться документный поиск |

Главная проблема: сейчас приложение пытается определить стратегию поиска по текстовым шаблонам.
А должно определять намерение пользователя и выбирать соответствующую операцию.

2. Большой документ загружается последовательно и обрезается

В коде есть:

```shell
MAX_CONTEXT_CHARS = 12000
MAX_SUMMARY_CONTEXT_CHARS = 18000
```

Когда пользователь просит описать акт, выполняются:
```shell
documents = load_document_chunks(document_name)

context = build_context(
    documents,
    MAX_SUMMARY_CONTEXT_CHARS,
)
```

Поэтому при документе на 100 страниц модель фактически видит только начало документа, а не весь документ.
Более того, при --max-model-len 4096 даже эти 18 000 символов вместе с системным промптом и ответом могут превысить разрешённое количество токенов.
Это две отдельные ошибки:
1. Превышение максимального контекста.
2. Потеря существенной части документа из-за обрезки.
   И увеличение --max-model-len решит только часть первой проблемы.
